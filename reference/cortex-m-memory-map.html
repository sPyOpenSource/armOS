ARM Cortex-M Memory Map & Vector Table

4GB Address Space

Cortex-M3/M4 have a flat 32-bit address space (4 GiB). ARM divides it into regions:

Address RangeRegionPurpose
0x00000000 – 0x1FFFFFFFCodeFlash, ROM, or aliased to SRAM. Vector table lives here at boot.
0x20000000 – 0x3FFFFFFFSRAMOn-chip RAM (static & heap). Bit-band region for atomic bit ops.
0x40000000 – 0x5FFFFFFFPeripheralGPIO, USART, SPI, TIM, etc. All memory-mapped registers.
0x60000000 – 0x9FFFFFFFExternal RAM / DeviceFSMC, SDRAM, external memory controllers.
0xE0000000 – 0xFFFFFFFFSystemNVIC, MPU, SysTick, debug (SCS). Not flash; CPU internal.

Boot-time alias

At reset, the region 0x00000000 is aliased to whatever memory the chip boots from (usually flash at 0x08000000 on STM32, or 0x00080000 on SAM3X). The CPU reads the initial SP from 0x00000000 and Reset_Handler from 0x00000004.

Vector Table

The vector table is an array of function pointers starting at address 0x00000000. Entry 0 is the initial stack pointer, entries 1–15 are system exceptions, and entry 16+ are peripheral IRQs.

OffsetException #NameDescription
0x00—_estackInitial SP (top of RAM)
0x041Reset_HandlerFirst code executed
0x082NMI_HandlerNon-maskable interrupt
0x0C3HardFault_HandlerUnexpected fault
0x104MemManage_HandlerMPU violation
0x145BusFault_HandlerBus error
0x186UsageFault_HandlerUndefined instruction, unaligned
… reserved …
0x4015SysTick_HandlerSystem tick timer
0x4416first peripheral IRQChip-specific (TIM, USART, etc.)

Each entry is 4 bytes (a 32-bit address). Peripheral IRQ lines start at offset 0x40 + 4 × n where n is the IRQ number.

Vector table placement

The table must be 4-byte aligned (256-byte aligned on some chips). It is typically placed in flash at the beginning of the .vectors / .isr_vector linker section:

KEEP(*(.vectors .vectors.*))     /* SAM3X style */
KEEP(*(.isr_vector))              /* STM32 style */

The vector table is defined in assembly startup files:

  • stm32: stm32_it.c (also uses CMSIS startup via system_stm32.c)
