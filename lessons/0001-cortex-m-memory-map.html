Lesson 1: Where Does Everything Live?

The ARM Cortex-M Memory Map & Vector Table

Mission tie-in: When you port armOS to a new Cortex-M chip, the first thing you need to know is where things are in the address space. The linker script, vector table, and startup code all revolve around this map.

1. The 4 GiB Playground

A Cortex-M CPU has a 32-bit address bus — 4,294,967,296 unique addresses. ARM partitions this space into large regions, each with a fixed purpose:

StartEndRegionWhat lives here
0x000000000x1FFFFFFFCodeFlash, ROM, or aliased boot memory
0x200000000x3FFFFFFFSRAMStatic data, heap, stack
0x400000000x5FFFFFFFPeripheralsGPIO, USART, SPI, ADC, …
0x600000000x9FFFFFFFExternal RAMSDRAM, FSMC, NAND
0xE00000000xFFFFFFFFSystemNVIC, SysTick, MPU, Debug
Rule of thumb: Every Cortex-M chip maps its flash somewhere in the Code region and its SRAM at 0x20000000. The rest (peripherals, system) varies per vendor but always falls in the same region.

Open your ports/stm32/boards/stm32f103xe.ld — you'll see:

MEMORY
{
    FLASH (rx)   : ORIGIN = 0x08000000, LENGTH = 512K
    RAM (xrw)    : ORIGIN = 0x20000000, LENGTH = 64K
}

Flash at 0x08000000 (Code region), RAM at 0x20000000 (SRAM region). Textbook Cortex-M.

Now open ports/atmel-sam3x/flash.ld:

MEMORY
{
    rom (rx)     : ORIGIN = 0x00080000, LENGTH = 512K
    sram0 (rwx)  : ORIGIN = 0x20000000, LENGTH = 64K
    ram (rwx)    : ORIGIN = 0x20070000, LENGTH = 96K
}

Same SRAM base. Flash is at 0x00080000 — still in the Code region, just a different spot. Each chip vendor chooses its own flash base within the Code region.

2. The Boot-Time Mirage: Aliasing

Here's where it gets interesting. At reset, the CPU doesn't know where your flash is. It blindly reads two values from address 0x00000000:

  • First word → initial Stack Pointer
  • Second word → address of Reset_Handler

But your flash is at 0x08000000 (STM32) or 0x00080000 (SAM3X), not at 0x00000000. How does this work?

The chip aliases the boot memory to 0x00000000. On STM32, 0x00000000 is a mirror of 0x08000000 at reset. The CPU sees your vector table at 0x00000000, reads the SP and reset vector, and starts executing.

Key insight for porting: You must place the vector table at the beginning of your flash region. The chip's boot logic ensures it appears at 0x00000000.

3. The Vector Table

The vector table is just an array of 32-bit addresses. Entry 0 is the stack pointer; entry 1 is the reset handler; entries 2–15 are system exceptions (faults, SVCall, SysTick); entry 16 onward are your chip's peripheral IRQs.

OffsetExceptionHandler name
0x00—_estack (initial SP)
0x04ResetReset_Handler
0x08NMINMI_Handler
0x0CHardFaultHardFault_Handler
0x10MemManageMemManage_Handler
0x14BusFaultBusFault_Handler
0x18UsageFaultUsageFault_Handler
………
0x40SysTickSysTick_Handler
0x44IRQ 0First chip-specific peripheral

Each entry is 4 bytes. The linker places this table at the very start of flash via the .vectors or .isr_vector section:

KEEP(*(.vectors .vectors.*))     /* SAM3X: flash.ld line 50 */
KEEP(*(.isr_vector))              /* STM32: common.ld line 10 */

4. A Quick Look at the Boot Sequence

Here's what happens from power-on to your main():

  1. CPU reads [0x00000000] → SP, [0x00000004] → Reset_Handler PC.
  2. Jumps to Reset_Handler (defined in startup_sam3x.c or CMSIS startup_*.s).
  3. Reset_Handler calls SystemInit (clock config, FPU enable, etc.).
  4. Calls _start or equivalent: copies .data from flash to RAM, zeroes .bss.
  5. Calls main().

Steps 3–4 are why the linker script defines symbols like _sdata, _edata, _sbss, _ebss.

5. Skill Practice: Map Your Own Chip

Find the linker script and startup file for the sam3x port, then answer:

  1. What is the flash base address? Where is the SRAM base?
  2. What value does the initial stack pointer get set to? (look for _estack or __StackTop)
  3. Where is the vector table defined — in which file?
  4. What is the first IRQ handler in the vector table (at index 16)?

Open ports/atmel-sam3x/flash.ld and ports/atmel-sam3x/startup_sam3x.c to check your answers.

Check your answers
  1. Flash: 0x00080000, SRAM: 0x20000000 (sram0), with another at 0x20070000 (ram).
